### 1. Neural / Semantic Web Search

**Endpoint:** `POST /search`
**SDK:** `exa.search(query, options)` (Python: `exa_py`; TypeScript: `exa-js`)
**Category:** search

**Purpose:** Full-web semantic search using embedding-based neural retrieval. Returns ranked URLs, titles, publish dates, authors, images, favicons, and optional inline contents. The core Exa primitive on which all higher-level features are built.

**Key Parameters:**
- `query` (required, string) — natural language or "link-style" query
- `type` — `"auto"` (default ~1s), `"instant"` (~250ms), `"fast"` (~450ms), `"deep-lite"` (~4s), `"deep"` (4–15s), `"deep-reasoning"` (12–40s)
- `numResults` — 1–100 (default 10)
- `category` — `"company"`, `"research paper"`, `"news"`, `"personal site"`, `"financial report"`, `"people"`, `"pdf"`
- `includeDomains` / `excludeDomains` — whitelist/blacklist up to 1200 domains
- `startPublishedDate` / `endPublishedDate` — ISO 8601 date filters
- `startCrawlDate` / `endCrawlDate` — crawl discovery date filters
- `includeText` / `excludeText` — phrase-must-contain / phrase-must-exclude (max 1 phrase, 5 words each)
- `userLocation` — ISO-3166-1 alpha-2 country code for geo-biasing
- `moderation` — content safety filter (default false)
- `contents` — inline content options (see Contents Retrieval feature)
- `outputSchema` — JSON Schema for synthesized structured output (works with all search types)
- `systemPrompt` — instructions guiding synthesized output
- `stream` — SSE streaming (only when outputSchema is provided)
- `additionalQueries` — up to 10 extra queries for deep-search variants

**FOSS Candidates:**
- `duckduckgo-search` (pypi) — DuckDuckGo scraper, no API key
- `searxng` (pypi/self-hosted) — meta-search engine aggregating multiple engines
- `brave-search` (pypi) — Brave Search API free tier (1000 req/month)
- `ddgr` (pypi) — DuckDuckGo CLI results
- `googlesearch-python` (pypi) — Google scraper (TOS-fragile)
- `SearXNG` (Docker) — self-hosted aggregator covering Google/Bing/DDG/Startpage
- `Kagi` (api) — paid, not FOSS
- For neural/embedding re-ranking over fetched results: `sentence-transformers` (pypi), `fastembed` (pypi)

### 2. Contents Retrieval (Text Extraction from URLs)

**Endpoint:** `POST /contents`
**SDK:** `exa.get_contents(urls, options)` / `exa.getContents(urls, options)`
**Category:** scrape

**Purpose:** Retrieve full page text, highlights, and/or per-page summaries for up to 100 known URLs in a single call. Returns instant results from Exa's cache; falls back to live crawl if missing or stale.

**Key Parameters:**
- `urls` or `ids` (required, array, 1–100) — URLs or search result IDs
- `text` — `true` (full markdown text) or object with:
  - `maxCharacters` — character cap
  - `includeHtmlTags` — preserve HTML tags
  - `verbosity` — `"compact"` (default) | `"standard"` | `"full"`
  - `includeSections` / `excludeSections` — semantic section filter: `header`, `navigation`, `banner`, `body`, `sidebar`, `footer`, `metadata`; requires `maxAgeHours: 0`
- `highlights` — `true` or object with `query` (highlight query string), `maxCharacters`
- `summary` — object with `query` (tailoring string), `schema` (JSON Schema for structured summary)
- `extras` — `{ links: N, imageLinks: N }` — extract N outbound links or image URLs per page
- `maxAgeHours` — freshness control: `0`=always livecrawl, `-1`=cache only, `N`=use cache if fresher than N hours (max 720), omit=smart fallback
- `livecrawlTimeout` — timeout in ms for livecrawl (0–90000, default 10000)
- `subpages` — integer 0–100, crawl linked subpages within the same domain
- `subpageTarget` — string or array of strings to target specific subpage topics
- `filterEmptyResults` — drop results with no content (default true)
- `compliance` — `"hipaa"` enterprise mode

**FOSS Candidates:**
- `playwright` (npm/pypi) — headless Chromium; handles JS-rendered pages; `page.content()`
- `puppeteer` (npm) — headless Chrome
- `crawlee` (npm) — full web crawling framework with Playwright/Cheerio/Puppeteer backends
- `cheerio` (npm) — jQuery-like HTML parsing
- `@mozilla/readability` (npm) — Mozilla's readability algorithm (same as Firefox Reader Mode)
- `turndown` (npm) — HTML-to-Markdown conversion
- `python-readability` (pypi) — Python port of readability
- `newspaper4k` (pypi) — article extraction with NLP metadata (title, authors, date, keywords)
- `trafilatura` (pypi) — main-content extraction with boilerplate removal; very accurate
- `goose3` (pypi) — article text extractor
- `html2text` (pypi) — HTML-to-Markdown
- `markdownify` (pypi) — HTML-to-Markdown
- `jusText` (pypi) — boilerplate removal
- `httpx` / `aiohttp` (pypi) — async HTTP fetching
- `requests-html` (pypi) — requests + pyppeteer for JS pages
- `bun` (runtime) — `Bun.fetch()` + `HTMLRewriter` for streaming HTML transforms

### 3. Content Highlights (Token-Efficient Snippets)

**Endpoint:** inline in `/search` (`contents.highlights`) or `/contents` (`highlights`)
**SDK:** `contents={"highlights": True}` / `highlights={"query": "...", "maxCharacters": N}`
**Category:** scrape / extract

**Purpose:** Return the most query-relevant 1–10 text excerpts (up to ~4000 chars each) from each result page instead of the full text. Claims 10x token efficiency over full text for RAG use cases.

**Key Parameters:**
- `highlights: true` — default highlights (query-driven)
- `highlights.query` — override the relevance query for highlight selection
- `highlights.maxCharacters` — max characters per highlight
- `highlightScores[]` — relevance scores per highlight

**FOSS Candidates:**
- `rank_bm25` (pypi) — BM25 scoring for sentence-level relevance
- `sentence-transformers` (pypi) — embedding-based snippet ranking with cosine similarity
- `spacy` (pypi) — sentence segmentation + TF-IDF for extractive snippets
- `sumy` (pypi) — extractive summarization (Luhn, TextRank, LSA)
- `lexrank` (pypi) — graph-based extractive summarization

### 4. LLM Summary Per Page

**Endpoint:** inline in `/search` or `/contents` (`summary`)
**SDK:** `contents={"summary": {"query": "...", "schema": {...}}}`
**Category:** answer-summarize

**Purpose:** Return an LLM-generated (Gemini Flash) abstractive summary of each page, optionally shaped by a query string or validated against a JSON Schema.

**Key Parameters:**
- `summary.query` — tailoring query for the summary
- `summary.schema` — JSON Schema for structured summary output (parsed JSON string back)

**FOSS Candidates:**
- `ollama` (local) with `llama3`, `mistral`, or any GGUF model for local summarization
- `transformers` (pypi) — HuggingFace summarization pipelines (BART, T5, PEGASUS)
- `sumy` (pypi) — extractive (no LLM required)
- `bertopic` (pypi) — topic-based summarization
- `openai` SDK pointed at local `llama.cpp` / `text-generation-inference` for drop-in replacement

### 5. Grounded Answer Endpoint

**Endpoint:** `POST /answer`
**SDK:** `exa.answer(query, options)` / `exa.streamAnswer(query, options)`
**Category:** answer-summarize

**Purpose:** Given a natural-language question, Exa searches internally, then an LLM synthesizes a direct answer or detailed summary with inline citations. Returns `answer` (string or structured JSON) + `citations[]` (result objects). Supports SSE streaming.

**Key Parameters:**
- `query` (required) — natural language question
- `text` — include full page text with citations (default false)
- `outputSchema` — JSON Schema for structured answer (returns object instead of string)
- `stream` — SSE streaming

**FOSS Candidates:**
- Build equivalent: search (DDG/SearXNG) + scrape (`trafilatura`/`playwright`) + summarize (local LLM via `ollama`/`llama.cpp`)
- `langchain` (pypi) — `WebResearchRetriever` + QA chain
- `llama-index` (pypi) — `WebPageReader` + query engine
- `haystack` (pypi) — `WebSearch` + `ExtractiveQAPipeline`
- `instructor` (pypi) — structured LLM output from any provider

### 6. Structured Output / Schema Extraction (outputSchema)

**Endpoint:** inline in `/search`, `/answer`, `/agent/runs`
**SDK:** `output_schema={...}` parameter on search/answer/agent
**Category:** extract

**Purpose:** Pass a JSON Schema to any search endpoint; Exa synthesizes and validates a structured JSON object from multiple sources. Enables entity extraction, list building, and report generation without manual parsing.

**Key Parameters:**
- `outputSchema` — JSON Schema draft-07/2019-09/2020-12; root type `"text"` or `"object"`
- `systemPrompt` — instruct the synthesis LLM
- `output.content` — synthesized text or structured JSON
- `output.grounding[]` — per-field citations array

**FOSS Candidates:**
- `instructor` (pypi) — structured extraction from any LLM (Pydantic models)
- `marvin` (pypi) — AI functions for structured extraction
- `kor` (pypi) — extraction schema over LLM output
- `outlines` (pypi) — constrained generation for structured outputs
- `json-repair` (pypi) — repair malformed LLM JSON output
- `pydantic` (pypi) — validation layer

### 7. Subpage Crawling

**Endpoint:** `POST /contents` with `subpages` and `subpageTarget`
**SDK:** `get_contents(urls, subpages=N, subpage_target=["term1","term2"])`
**Category:** crawl

**Purpose:** Given a root URL, automatically discover and fetch linked subpages within the same domain. Prioritizes subpages whose content matches `subpageTarget` terms. Up to 100 subpages per root URL.

**Key Parameters:**
- `subpages` — integer 0–100 (number of subpages to crawl)
- `subpageTarget` — string or string[] of terms to prioritize subpage selection
- `maxAgeHours` — freshness for crawled subpages
- `livecrawlTimeout` — timeout per live crawl request

**FOSS Candidates:**
- `crawlee` (npm) — production crawling framework with link discovery, BFS/DFS strategies, robots.txt, rate limiting
- `scrapy` (pypi) — full spider framework with link extraction (`LinkExtractor`), depth limits, middleware
- `playwright` (npm/pypi) — extract all `<a href>` tags, follow to depth N
- `spider` (npm: `@spider-cloud/spider-client`) — cloud-based but has OSS WASM engine
- `colly` (Go) — concurrent web scraper with callbacks
- Custom BFS: `httpx` + `BeautifulSoup4` + `lxml` + URL queue
- `linkchecker` (pypi) — link discovery without content
- `aiohttp` + `asyncio` — async BFS crawler

### 8. Live Crawl / Content Freshness

**Endpoint:** `maxAgeHours` parameter in `/contents` and `/search`
**SDK:** `max_age_hours=N` or `maxAgeHours: N`
**Category:** scrape

**Purpose:** Control whether Exa serves cached or freshly fetched page content. `maxAgeHours=0` always fetches live. `maxAgeHours=-1` never fetches live. Omit for smart fallback. Deprecated `livecrawl` string parameter maps to these values.

**Key Parameters:**
- `maxAgeHours` — integer -1 to 720; `0`=always fresh, `-1`=cache-only, `N`=max age, omit=fallback
- `livecrawlTimeout` — per-request ms timeout for live fetch (0–90000)

**FOSS Candidates:**
- `httpx` / `aiohttp` — direct live HTTP fetch, no cache layer
- `requests-cache` (pypi) — transparent HTTP cache with TTL
- `hishel` (pypi) — HTTPX-compatible caching middleware (RFC 9111)
- `cachier` (pypi) — function-level caching with TTL
- `redis` — store HTML/text keyed by URL + TTL for custom cache layer
- `diskcache` (pypi) — disk-backed cache with TTL

### 9. Vertical / Category Search

**Endpoints:** `/search` with `category` parameter
**SDK:** `category="company"` | `"people"` | `"news"` | `"research paper"` | `"financial report"` | `"personal site"` | `"pdf"`
**Category:** search

**Purpose:** Route search queries to specialized indexes optimized for specific content types. Returns structured `entities[]` metadata for `company` and `people` categories.

**Sub-features:**

#### 9a. News Search
- Real-time news index across major/niche publications
- `category="news"` + `startPublishedDate`/`endPublishedDate` for recency
- **FOSS:** `gnews` (pypi), `feedparser` (pypi) + RSS, `newspaper4k` (pypi), `newsapi-python` (pypi, free tier), `pygooglenews` (pypi)

#### 9b. People Search (1B+ profiles)
- Returns `entities[].properties`: `name`, `firstName`, `lastName`, `location`, `workHistory[]{title, company, dates}`, `educationHistory[]{degree, institution, dates}`
- `category="people"`, `includeDomains` limited to supported profile domains
- **FOSS:** `linkedin-scraper` (pypi, TOS-risk), `proxycurl` (paid API), build from `requests` + profile parsing

#### 9c. Company Search (50M+ companies)
- Returns `entities[].properties`: `name`, `foundedYear`, `description`, `workforce.total`, `headquarters{address, city, postalCode, country}`, `financials{revenueAnnual, fundingTotal, fundingLatestRound{name, date, amount}}`, `webTraffic{visitsMonthly, countryRank, avgDurationSeconds}`
- `category="company"`
- **FOSS:** `clearbit` (limited free), `opencorporates` (API free tier), build from SerpAPI company results + scraping

#### 9d. Code Search (GitHub, StackOverflow, Docs)
- Indexes GitHub repos, SO posts, documentation pages
- Semantic search for code patterns, configurations, API usage
- **FOSS:** `github-search` (GitHub API free), `stackoverflow-api` (python-stackoverflow), `grep.app` (web scrape), `sourcegraph` (self-hosted OSS)

#### 9e. Research Paper Search (100M+ papers)
- Full-text PDFs, metadata, authors, abstracts
- **FOSS:** `semanticscholar` (pypi — Semantic Scholar API), `arxiv` (pypi), `scholarly` (pypi — Google Scholar), `unpaywall` (pypi)

#### 9f. Financial Report Search
- SEC 10-K filings, Yahoo Finance
- **FOSS:** `sec-edgar-downloader` (pypi), `yfinance` (pypi), `edgartools` (pypi)

### 11. Monitors (Scheduled Recurring Search)

**Endpoint:** `POST /monitors`, `POST /monitors/{id}/trigger`, `GET /monitors/{id}/runs`
**SDK:** `exa.monitors.create(params)`, `exa.monitors.trigger(id)`, `exa.monitors.runs.list(id)`
**Category:** monitor

**Purpose:** Set up recurring Exa searches on an interval schedule. Each run automatically deduplicates against previous run results (date-based filtering + semantic dedup). Results delivered to a webhook URL. Supports structured JSON output via `outputSchema`.

**Key Parameters (create):**
- `search.query` (required) — search query
- `search.numResults` — results per run
- `search.contents` — full contents options (text, highlights, summary, extras, maxAgeHours, subpages)
- `trigger.type` — `"interval"`
- `trigger.period` — `"6h"`, `"1d"`, `"7d"`, etc.
- `webhook.url` (required) — delivery endpoint (no redirects)
- `webhook.events` — event types to deliver
- `outputSchema` — `{"type": "text"}` or `{"type": "object", "properties": {...}}` for structured output
- `metadata` — key-value echoed in webhook for routing (e.g., Slack channel IDs)
- Monitor status: `active`, `paused`, `disabled` (after 10 auth failures)

**FOSS Candidates:**
- `node-cron` (npm) + custom search + webhook: DIY scheduled search loop

## UNIQUE CAPABILITIES (Exa-specific, hard to replicate FOSS-for-free)

1. **Neural/embedding-based full-web search** — Exa trained custom models on link-style queries; FOSS alternatives (DDG/Brave) use keyword matching. To replicate: embed queries + cosine search over a crawled corpus with `sentence-transformers` + `faiss-cpu`.

2. **Highlights (10x token efficiency)** — Exa's proprietary model extracts only query-relevant sentences. FOSS: `rank_bm25` or `sentence-transformers` re-ranking over sentence windows.

3. **Structured entity metadata for company/people** — Pre-enriched `entities[]` payload with financials, headcount, work history. No direct FOSS equivalent; requires scraping LinkedIn (TOS) or paid data providers.

4. **Deep search types (deep-lite / deep / deep-reasoning)** — Multi-step search+synthesis in a single API call. FOSS: chain together DDG/Brave + `trafilatura` + local LLM pipeline manually.

5. **Monitor deduplication** — Semantic deduplication across recurring runs ensures only new content is surfaced. FOSS: MinHash LSH (`datasketch`) or SimHash on result text + Redis bloom filter.

6. **Agent runs with contact enrichment** — Native email/phone extraction from web pages at scale. FOSS: `phonenumbers` (pypi) + regex email extraction + `hunter.io` (paid) or manual scraping.

7. **Websets enrichment columns** — LLM-powered per-row enrichment as a managed async service. FOSS: `instructor` + async task queue (BullMQ/Celery).
