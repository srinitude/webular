# src/cli/AGENTS.md

Rules for the launcher and router, under [src/AGENTS.md](../AGENTS.md).

## What lives here

- [`route.ts`](route.ts) and [`dispatch.ts`](dispatch.ts) turn `webular <command>` into the command's own process. [`dispatch-table.ts`](dispatch-table.ts) is the generated list they read.
- [`commands.ts`](commands.ts) is the one list of commands and their one-line help. Help text and the router both read it.
- [`run.ts`](run.ts) runs a Mastra workflow for a command, then prints the result and sets the exit code. [`render.ts`](render.ts) holds one small human renderer per command.
- [`help.ts`](help.ts) and [`style.ts`](style.ts) shape terminal text: wrap, color, error labels, and "did you mean".
- [`launch.ts`](launch.ts) picks what runs: the native build, else Bun on `dist`, else Bun on `src`.
- [`exit-codes.ts`](exit-codes.ts) is the one source of exit codes.
- [`completion-script.ts`](completion-script.ts) builds the bash, zsh, fish, and PowerShell completion scripts for `webular completions`.

## Rules

- The CLI routes only. It never imports command code, so each command runs in its own process.
- [`dispatch-table.ts`](dispatch-table.ts) is generated by [`scripts/gen-dispatch.ts`](../../scripts/gen-dispatch.ts). Never edit it. Change [`mise.toml`](../../mise.toml), then run `mise run build`.
- Adding a command needs an entry in [`commands.ts`](commands.ts) and a renderer in [`render.ts`](render.ts). A missing renderer is a compile error.
- Machine data goes to stdout and notes go to stderr. Color only decorates, so the words must carry the meaning.
- Interrupts (`mise run bugs:effect`): Ctrl-C cancels the running workflow, so its steps and child processes stop.
- The `--json` shape is the agent contract. Ask first before you change it.

## Checks

```bash
mise run test:file tests/cli tests/machines/cli-dispatch.test.ts
```

A bad `-o` path fails before the workflow loads (slow sandbox rejects): `mise run bugs:tests-build`.
